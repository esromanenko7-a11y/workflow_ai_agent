# Векторное хранилище Qdrant

## Назначение

Векторное хранилище используется для хранения знаний о проверках качества пакета данных.

Документы содержат информацию о проверках:

- код проверки;
- название;
- категорию;
- критичность;
- описание;
- цель;
- требования;
- примечания.

Эти данные будут использоваться ИИ-ассистентом для анализа результатов проверок пакета и подготовки понятных рекомендаций пользователю.

## Конфигурация

EMBEDDING_DIM=384
```

```

Размерность вектора:

```text
384
```

Рабочая коллекция:

```text
documents
```

Основная метрика расстояния:

```text
COSINE
```

## Структура документов

Для каждой проверки создаётся несколько документов разных типов:

- `summary`;
- `description`;
- `objective`;
- `requirements`;
- `notes`.

Каждый документ хранит payload со следующими полями:

```text
source
text
created_at
check_code
check_name
category
severity
chunk_type
```

Всего сгенерировано:

```text
122 документа
```

В рабочей коллекции на момент эксперимента находилось 124 точки, так как дополнительно сохранялись две тестовые точки из раннего smoke-теста.

## Идемпотентная загрузка

Для идентификаторов точек используется детерминированный `UUID5`.

Одинаковый документ при каждом запуске получает одинаковый идентификатор. Поэтому повторная загрузка не создаёт дубликаты, а обновляет существующие точки.

Результат проверки:

```text
После первого запуска: 124 точки
После повторного запуска: 124 точки
```

## Модуль VectorStore

Модуль:

```text
app/services/vector_store.py
```

является тонкой обёрткой над `AsyncQdrantClient`.

Клиент Qdrant создаётся один раз и повторно используется в приложении.

### ensure_collection

```python
async def ensure_collection(self) -> None:
    ...
```

Метод:

- проверяет наличие коллекции;
- создаёт коллекцию, если она отсутствует;
- проверяет размерность существующей коллекции;
- создаёт payload-индексы.

Если размерность коллекции не совпадает с `EMBEDDING_DIM`, выполнение завершается с понятной ошибкой.

### upsert

```python
async def upsert(
    self,
    points: list[PointStruct],
    batch_size: int = 256,
) -> None:
    ...
```

Метод загружает точки батчами.

Последний батч отправляется с параметром:

```python
wait=True
```

Это позволяет выполнять поиск сразу после завершения загрузки.

### search

```python
async def search(
    self,
    query_vector: list[float],
    top_k: int = 5,
    query_filter: Filter | None = None,
) -> list[ScoredPoint]:
    ...
```

Метод выполняет семантический поиск через `query_points()` и возвращает список объектов `ScoredPoint`.

### get_points_count

```python
async def get_points_count(self) -> int:
    ...
```

Метод возвращает текущее количество точек в коллекции.

## Payload indexes

Созданы индексы для полей:

```text
source
created_at
category
```

Назначение индексов:

- `source` — фильтрация по источнику документа;
- `created_at` — фильтрация по дате создания;
- `category` — фильтрация по предметной категории проверки.

Поле `category` является предметным полем дипломного проекта.

Примеры категорий:

```text
Проверка структуры пакета
Проверка meta-файла
Проверка data-файлов
```

## Фильтрация по metadata

### Match по строке

Фильтр ограничивает поиск документами из категории:

```text
Проверка meta-файла
```

Код фильтра:

```python
from qdrant_client.models import (
    FieldCondition,
    Filter,
    MatchValue,
)

query_filter = Filter(
    must=[
        FieldCondition(
            key="category",
            match=MatchValue(
                value="Проверка meta-файла",
            ),
        ),
    ],
)
```

Тестовый запрос:

```text
meta файл
```

Top-3 результата:

| Код проверки | Тип документа | Категория |
|---|---|---|
| `META_FILE_FORMAT` | `objective` | Проверка meta-файла |
| `META_FILE_FORMAT` | `requirements` | Проверка meta-файла |
| `META_FILE_FORMAT` | `description` | Проверка meta-файла |

Фильтр сработал корректно: в выдаче отсутствовали документы из других категорий.

### Range по дате

Фильтр выбирает документы, созданные за последние 30 дней.

```python
from datetime import datetime, timedelta, timezone

from qdrant_client.models import (
    DatetimeRange,
    FieldCondition,
    Filter,
)

date_from = datetime.now(timezone.utc) - timedelta(days=30)

query_filter = Filter(
    must=[
        FieldCondition(
            key="created_at",
            range=DatetimeRange(
                gte=date_from,
            ),
        ),
    ],
)
```

Поле `created_at` хранится в payload и имеет индекс типа `DATETIME`.

Фильтр позволяет исключить устаревшие документы и использовать только актуальные версии знаний.

Фактические top-3 результаты для этого фильтра необходимо зафиксировать после запуска отдельного smoke-теста диапазона дат.

### Композитный фильтр must + must_not

Для предметной области проекта используется следующий аналог production-фильтра:

- искать только проверки категории `Проверка meta-файла`;
- исключать вспомогательные документы типа `notes`.

```python
from qdrant_client.models import (
    FieldCondition,
    Filter,
    MatchValue,
)

query_filter = Filter(
    must=[
        FieldCondition(
            key="category",
            match=MatchValue(
                value="Проверка meta-файла",
            ),
        ),
    ],
    must_not=[
        FieldCondition(
            key="chunk_type",
            match=MatchValue(
                value="notes",
            ),
        ),
    ],
)
```

Такой фильтр ограничивает поиск предметной категорией и одновременно исключает документы, которые не должны попадать в основной контекст ответа.

Фактические top-3 результаты для этого фильтра необходимо зафиксировать после запуска отдельного smoke-теста.

## HNSW

В проекте оставлены стандартные параметры HNSW Qdrant:

```text
m = 16
ef_construct = 100
```

Для текущего учебного объёма данных отдельная настройка HNSW не требуется.

Причины оставить параметры по умолчанию:

- коллекция содержит немногим более 100 документов;
- скорость поиска уже достаточна;
- дополнительная настройка не даст заметной пользы на текущем объёме;
- стандартные параметры обеспечивают разумный баланс скорости, памяти и качества поиска.
